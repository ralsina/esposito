Esposito OS — Architecture

Dynamic app-loading OS for ESP32 CYD · event-driven · single-tasking · Palm-style lifecycle

Architecture Model

  • • Event-driven: central event queue, apps subscribe in app_init()
  • • Single-tasking: one app runs at a time, OS manages switching
  • • Palm-style lifecycle: init → event → checkpoint → close
  • • Dynamic ELF loading from SD card (relocatable, symtab-resolved)
  • • Apps fully trusted — no sandboxing (personal device model)
  • • Layered: apps → API surface → OS core → HAL/drivers → hardware

Build & Update Paths

  • • ESP-IDF firmware: idf.py build / flash / monitor
  • • Per-app ELFs: scripts/build_app.sh (deps file → link libs)
  • • Linux SDL2 emulator: linux/run.sh [app] for host testing
  • • OTA: Settings app → ota_update → TLS download → verify → flash
  • • SD card update: /system/firmware.bin checked at boot → stub
  • • Flash partitions: factory(2MB) · app_code · update(ota_0) · NVS

App Ecosystem

  • • 23 apps: launcher, settings, shell, clock, reader, kilo, paint, games…
  • • manifest.cfg: name, launcher visibility, file extensions
  • • deps file: link shared libs (ui2, json, arduboy, lua, serial_rx)
  • • ui2: widget toolkit (button, list, toolbar, OSK, tabview, icons)
  • • File associations → "Open with" via app_manifest_find_apps_for_ext
  • • Per-app config namespace auto-bound before app_init()
